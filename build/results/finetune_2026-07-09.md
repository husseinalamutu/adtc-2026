# Final fine-tune — 2026-07-09

First real fine-tune on the **complete** dataset. This is the submission model's adapter.

## Setup
- Base: `mlx-community/Qwen2.5-3B-Instruct-4bit` (true 4-bit QLoRA — see mlx_lora_config.yaml header)
- Dataset: 3,025 train / 370 holdout = 3,000 templated (arithmetic) + 248 advisory (Gemini/Groq)
  + 149 Nigeria-tax (Groq, fact-grounded). Split by scenario family (hidden-prompt proxy).
- LoRA: all 36 layers, all 7 attention+MLP modules, rank 32, seq 1024, grad-accum 4, lr 1e-5.
  1.94% trainable (59.9M params). Peak mem ~3.9 GB on the 8GB Mac.

## Validation-loss trajectory (val_batches=15, so ±0.03 sampling noise)
| global iter | val loss |
|---|---|
| 0 (baseline) | 2.175 |
| 100 | 0.490 |
| 200 | 0.459 |
| **300** | **0.424 (best)** |
| 400 | 0.452 |
| 500 | 0.455 |

**Plateaued around global 200–300** (~0.5–0.7 epochs). Stopped at global ~500 rather than the
configured 1200: val loss had been flat/noisy in the 0.42–0.46 band for 300 iters with no
improvement, so further training was pure resume-cycle cost for zero gain (and eventual
overfit risk). Selected the **global-300 checkpoint (val 0.424)** as the submission adapter;
preserved at `adapters_best/global0300_val0424.safetensors`.

## Operational notes
- Training ran DETACHED (nohup) with checkpoints every 100 iters + `resume_training.sh`
  (global-offset tracking via `adapters/base_offset.txt`) to survive session teardowns — it
  took ~3 launches to reach global 500.
- Baseline val 2.175 → 0.424 is a large, clean drop on held-out data: the model genuinely
  learned the SME back-office + Nigeria-tax domain, not memorization (holdout families unseen).
